## 1. 技術選定

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | TypeScript（strict） | 9モードの教材・判定・保存の型を一か所で保守するため |
| UI | React 18 | 画面の状態管理が多く、部品を共有しやすい。依存が少なく安定 |
| ビルド | Vite | 開発が速い。静的ファイルとして配布できる |
| ルーティング | 自前のハッシュルーター（約50行） | 必要なのは5種類の画面だけ。`#/mode/shopping` のようにし、ブラウザの「戻る」と再読み込みに対応 |
| PWA | 自前の Service Worker + Vite プラグインでプリキャッシュ一覧を生成 | 版ごとの一括キャッシュ（OF-05）を確実に制御するため。vite-plugin-pwa（Workbox）は高機能だが依存が大きく、今回の要件には不要 |
| 保存 | IndexedDB（自前の薄いラッパー） | 作品（線のデータ）や記録が増えても容量に余裕がある。localStorage は同期APIで容量が小さい（5MB前後）ため、軽い設定以外に使わない |
| なぞり | Canvas 2D | 指の軌跡を高頻度で描くため。判定は描画と切り離した純粋関数 |
| 盤面・図形・比較 | SVG（React） | 正確な座標・同一座標系での比較（M6-07）、吸着判定がしやすい |
| 音声 | Web Audio API（同梱 mp3 を decode して再生） | 重複防止・停止・音量を一か所で制御。mp3 は Chromium/Firefox 両方で再生可能 |
| 効果音 | Web Audio で合成（ファイルなし） | 柔らかい短音のみ。素材のライセンス管理が不要 |
| テスト | Vitest（単体）、Playwright（E2E: Chromium・Firefox） | 判定ロジックは純粋関数で網羅、主要フローはE2E |
| 品質 | ESLint、Prettier、tsc | NF-03 |

依存ライブラリ（実行時）: `react`, `react-dom` のみ。開発時: vite, @vitejs/plugin-react, typescript, vitest, fake-indexeddb, @playwright/test, eslint 一式, prettier, tsx。すべて版を完全固定。

## 3. 画面遷移

```
[起動画面] ──はじめる（音声有効化）──▶ [プロフィール選択]※2人以上のとき
                                          │
                                          ▼
                                       [ホーム] ◀──────────────┐
             ┌───────────────┬────────┼──────────┐               │
             ▼               ▼        ▼          ▼               │
     [モード: 段階選択]※  [がんばりノート] [鍵 長押し2秒]          │
             │                                 ▼                 │
             ▼                          [大人の確認問題]            │
     [問題 1..N] ─完了─▶ [完了画面] ─もういっかい─▶[問題 1..N]      │
             │               └─おうち──────────────────────────┤
             └─おうち（いつでも、途中保存）───────────────────────┘
                                                ▼
                                         [保護者画面（タブ）]
                                  きろく / せってい / さくひん / メモ /
                                  プロフィール / データ / このアプリについて
```
※段階選択: さんすう（たす・ひく・わける・しき）、みちをつくろう（もんだい・じゆう）、なぞってあそぼう（せん・かたち・もじ）のように、子供が遊び方を絵で選ぶ画面。進度は遊び方ごとに独立。

ルート（ハッシュ）:

| ハッシュ | 画面 |
|---|---|
| `#/` | 起動画面（音声未有効のときは常にここから） |
| `#/home` | ホーム |
| `#/play/<modeId>` | モード（遊び方選択がある場合はその画面） |
| `#/play/<modeId>/<variantId>` | モードの実行 |
| `#/notebook` | がんばりノート |
| `#/parent/<tab>` | 保護者画面（ゲート通過済みのセッションのみ。再読み込み時は再確認） |

### 子供のユーザーフロー（例）
1. デスクトップのアイコンをタップ → 起動画面「はじめる」（大きな緑の札）をタップ。音声が有効になり「まなびのにわへ ようこそ」。
2. ホーム: 上段に「きょうの おすすめ」2〜3枚、下段に9モード。絵をタップ → 名前を読み上げてモードへ。
3. モード: 問題文を音声で聞く → 操作 → 判定 → 次の問題（自動で進むのではなく、正解後に「つぎ」の札、または短い演出の後に自動。モードごとに定義）。
4. 4問で完了画面: 行ったことを言葉と絵で示す。「もういっかい」「おうち」「すき（ハート）」。
5. 利用時間の目安に達していたら、完了画面の後に「きょうは ここまで」画面（「おうち」だけを出す。保護者は延長可）。

### 保護者のユーザーフロー
1. ホーム右上の鍵ボタンを2秒長押し（押している間、輪が満ちる表示）。
2. 大人の確認問題（例「27 ＋ 45 は？」を数字ボタンで入力）。暗証番号を設定した場合は暗証番号。
3. 保護者画面で、記録・設定・作品・メモ・プロフィール・データ管理・更新を操作。
4. 「こどもの がめんに もどる」でホームへ。

保護者ゲートは**誤操作の防止**であり認証ではない。暗証番号も端末内に保存され、ブラウザの開発者ツールで回避できる（README・保護者画面に明記）。

## 4. モードの共通の仕組み

### 4.1 モード定義（src/modes/registry.ts）

```ts
interface ModeDef {
  id: ModeId;                 // 'shopping' | 'hiragana' | ... 9種
  title: string;              // ひらがな名（子供向け）
  titleVoice: VoiceKey;       // 名前の読み上げ
  icon: IllustId;             // ホームのイラスト
  variants: VariantDef[];     // 遊び方（1つ以上）。1つだけなら選択画面を出さない
  homeTips: string[];         // おうちで ためせる あそび（保護者向け）
  load: () => Promise<{ default: ComponentType<ModePlayProps> }>; // 遅延読み込み
}
interface VariantDef {
  id: string; title: string; titleVoice: VoiceKey; icon: IllustId;
  skillId: SkillId | null;    // 進度を持たない遊び（じゆうにつくる）は null
  roundKind: 'questions' | 'work';
  available?: (p: ProgressSnapshot) => boolean; // 例: さんすう「しき」の解放条件
}
interface SkillDef { id: SkillId; modeId: ModeId; label: string; levels: LevelDef[] }
interface LevelDef { id: string; label: string; changedFactor: string; description: string }
```

### 4.2 実行枠（ModeRunner）とセッション

`ModeRunner` が全モード共通で以下を担い、モード本体（`ModePlayProps.session`）には必要な機能だけを渡す。

```ts
interface ModeSession {
  profileId: string;
  variantId: string;
  level: number;               // 現在の段階（0始まり）
  roundSize: number;           // 1回の問題数（3〜5）
  seed: number;                // この回の乱数seed
  settings: ChildSettings;     // 動きを減らす、判定幅など
  prompt(keys: VoiceSeq): void;   // 問題文を設定して再生（「もういちど きく」の対象）
  say(keys: VoiceSeq): Promise<void>; // 一時的な声かけ
  record(a: AttemptInput): void;      // 1問の結果を保存（進度更新もここ）
  finish(s: RoundSummary): void;      // 完了画面へ
  saveWork(w: WorkInput): Promise<string>; // 作品保存
  draft: DraftApi;                    // 中断データ（つづきから）
  expose(debug: unknown): void;       // E2E用。テストフラグが無効なら何もしない
}
```

- 画面上部の共通ヘッダー: 左「おうち」、右「もういちど きく」（音声再生中は波の表示）。ヘッダーはモード本体が描かない。
- 完了画面は `RoundSummary.sentences`（観測した行動に基づく声かけキー列）と `items`（行った問題の絵）から共通部品で描く。
- 入力ロック: `useAnswerLock()` で判定〜フィードバック中は入力を無視（OP-05）。遷移ボタンは1回押すと無効化。

### 4.3 選択式の問題の共通フロー（useChoiceQuestion）

ひらがな・おぼえてさがす・くらべっこ・さんすう（A〜C, E）で使う。

```
提示（prompt再生。音声だけが手がかりの問題は、最初の再生が終わるまで選択肢を無効表示。最大3秒）
  → 選択
  ├ 正解: ロック → 成功表示（○の印と声）→ 記録 → 次へ
  └ 不正解: wrongTries+1 → その選択肢を薄く＋「？」→
       1回目の誤答: ヒント1（注目点の声）を自動で出す
       2回目の誤答: ヒント2（具体的）を自動で出す
       ヒント2の後: 「つぎへ」の札も出す（押すと正解を見せて次へ = skipped）
```

**結果の種類の状態表（AD-05。1問につき1つ。上の行ほど優先）**

| 条件 | outcome | 進む判定 | 戻る判定 |
|---|---|---|---|
| 「おうち」等で途中終了 | `abandoned` | 数えない（窓に入れない） | 数えない |
| 1問の中で操作のとまどい（下記）があった | 結果はそのまま記録、`operationIssue=true` | 窓に入れない | 窓に入れない |
| 「つぎへ」で進んだ／3回目の誤答で正解を示した | `skipped` | — | 数える |
| ヒント2が出た後に正解（「ヒント」ボタンを2回押した場合も） | `after_hint` | — | 数える |
| 見直し（もういちど みる）を使って正解 | `after_review` | — | **数えない**（良い方略。罰にしない） |
| 誤答 → ヒント1 → 正解（またはヒントボタン1回の後に正解） | `self_corrected` | — | 数えない |
| 最初の選択で正解、ヒント・見直しなし | `independent` | 数える | — |

- `self_corrected` の声かけは「もういちど やって できたね」（誤答の後に選び直した、という観測できた事実）。
- さんすうE の「えで みる」は「見直し」と同じ扱い（`after_review`）。
- 操作のとまどい（`operationIssue`）: 1.5秒以内に3回以上の選択（違う選択肢を含む）、盤面外のタップが1問で10回以上、なぞりで極端に短い線が5本以上続く。誤答に数えず、進度の窓から除外し、保護者画面に別欄で出す（PA-09）。
- 選択式以外のモードの「1問」と各条件は learning-design.md 0章「モード別の問題の単位」に定義する。
- 正解位置: `balancedPositions()` で1回の中の正解位置を均等化し、同じ位置が3回続かないようにする。

### 4.4 進度ルール（src/core/progress/rules.ts, 純粋関数）

```
窓: 現在の段階での直近10件（abandoned・operationIssue 付きは入れない）
判定のタイミング: 1回（ラウンド）の終わりにだけ判定する。1問ごとには判定しない
進む: 段階が変わってから10件以上たまり、窓の10件中8件以上が independent → 次の段階
      （最上段なら mastered=true のまま段階は変わらない）
戻る: 段階が変わってから8件以上たまり、直近6件中 independent ≤ 1 かつ (after_hint + skipped) ≥ 4
      → 1段階戻る（第1段階より下には戻らない）
変化後: 窓を空にする（＝次の変化までに最低8〜10問かかる。上下の往復を防ぐ）
保護者が「こてい」にしたスキルは変化しない。保護者が段階を変えたときも窓を空にする
```
- 保護者画面には「この段階で 自分で できたのは 直近10問中 7問。8問で つぎの だんかいへ」のように理由を文章で出す（AD-09）。
- でたらめ連打の評価: 2択で毎回ランダムに押した場合、1回の判定で10件中8件以上が independent になる確率は約5.5%。判定はラウンド終わりごとに繰り返されるため、累積の確率は単体テストのシミュレーション（2択・4問/回・10回分）で算出し、結果を test-plan.md に記録する。さらに、連打は `operationIssue` として窓から除外されるため、実際にはこれより低い。誤って進んでも、戻る規則と保護者の固定で戻せる。

### 4.5 おすすめ（src/core/progress/recommend.ts, 純粋関数）

その日の日付と記録から2〜3件を決める（同じ日は同じ結果）。
1. 「すき」なモードから1件（今日まだ遊んでいないもの優先）。
2. 最近（3日以上）遊んでいないモード。
3. 進みかけ（段階の窓が5件以上で未達）のモード。
4. 数・文字・形・考える の領域が偏らないよう、同じ領域から2件選ばない。
今日2回以上遊んだモードは選ばない。データがない初回は「おかいものごっこ」「なかまわけ」「なぞってあそぼう」。

## 5. データ構造

### 5.1 教材データの共通語彙（src/content/vocab.ts）

```ts
interface VocabItem {
  id: IllustId;            // 'apple'
  label: string;           // 'りんご'（音声・表示の名前）
  voice: VoiceKey;         // 'item.apple'
  category?: 'animal' | 'food' | 'vehicle' | 'thing' | 'nature';
  color?: 'red' | 'yellow' | 'green' | 'blue' | 'brown' | 'white' | 'orange';  // 分類で使う単色のもの
  counter: 'ko' | 'hiki' | 'dai' | 'wa' | 'hon' | 'mai';  // 数え方
}
```
- 同じ絵は全モードで同じ部品・同じ名前（DESINGN.md の一貫性規約）。
- 分類に使う属性は「分類に使ってよい」ものだけを持たせる（例: トマトは category=food のみ。野菜/果物の区別は持たない）。
- 数え方: 4歳向けに、おかいもの・さんすう では原則「こ」を使う（りんご 3こ）。動物を数える問題では「ひき」。乗り物は数の問題に使わない。

### 5.2 音声

- 台本: `src/voice/catalog/*.ts` に `キー: 文` または `{ text, yomi }`。全キーを型 `VoiceKey` で表し、存在しないキーはコンパイルエラーになる。
- 合成文: 「りんごを 3こ ください」は `['shop.order.item.apple', 'count.ko.3', 'shop.please']` のように部品をつなぐ。
- 生成: `npm run voice:script` が台本を `voice/script.json` に出力 → `npm run voice:build` が Open JTalk で `public/audio/<key>.mp3` と `manifest.json` を差分生成（docs/assets-pipeline.md）。
- 実行時: `AudioEngine.play(keys)` は、再生中の列を止めてから新しい列を順に再生する。返り値の Promise は「最後まで再生」か「止められた」で解決する。
- 停止: ルート変更、`visibilitychange`（hidden）、`pagehide` で `stopAll()`。
- 欠損時: mp3 が取得できないキーは、`speechSynthesis`（ja-JP の声があるとき）で読み上げ。それもなければ無音で進み、`audioHealth` を `degraded` にして保護者画面に表示。

### 5.3 保存（IndexedDB: データベース名 `manabi-no-niwa`）

| ストア | キー | 内容 |
|---|---|---|
| `meta` | `'meta'` | `{ schemaVersion, createdAt, lastAppVersion }` |
| `app` | `'app'` | `{ activeProfileId, parentPinHash?, homeLastProfile }` |
| `profiles` | `id` | `{ id, name, avatar: IllustId, createdAt }` |
| `settings` | `profileId` | ChildSettings（音量、効果音、動きを減らす、利用時間、1回の問題数、ホーム表示、表示するモード、なぞり判定幅、記憶の自動かくし秒数、スキルの固定） |
| `progress` | `[profileId, skillId]` | `{ level, window: Outcome[], mastered, changedAt, lastChange: {from,to,reason} }` |
| `attempts` | 自動採番（索引: profileId+at） | `{ profileId, modeId, variantId, skillId, level, itemKey, outcome, wrongTries, hintsUsed, reviewsUsed, operationIssue, inputKind, at, detail }` |
| `rounds` | 自動採番（索引: profileId+at） | `{ profileId, modeId, variantId, startedAt, endedAt, count, completed }`（利用時間・がんばりノート用） |
| `works` | `id` | `{ id, profileId, modeId, kind: 'trace'|'road', title, createdAt, data }` |
| `memos` | `id` | `{ id, profileId, date, text }` |
| `drafts` | `[profileId, modeId, variantId]` | 中断した回の状態（24時間で破棄） |
| `favorites` | `profileId` | `{ modeIds: ModeId[] }` |

- attempts はプロフィールごとに最新 5,000 件を残し、古いものから削除（保護者画面に記載）。
- 書き込みはすべて try/catch。`QuotaExceededError` は `storageHealth='full'`、その他は `'error'` とし、保護者画面とホームの鍵ボタン付近に小さな印を出す（子供の操作は止めない）。
- `navigator.storage.persist()` は子供画面では呼ばない（Firefox で許可のダイアログが出る場合があるため）。保護者画面の「データを まもる」ボタンの操作で要求し、結果（`persisted()`）を表示する。
- なぞり作品の座標は整数（0〜1000）に丸めて保存し、書き出しファイルを小さく保つ。目安: 記録 5,000件 ≈ 1.5MB、なぞり作品 1件 ≈ 3KB。読み込み上限は 50MB とし、書き出し時に 40MB を超える場合はプロフィールごとの書き出しを勧める。

### 5.4 スキーマのバージョンと移行

- `SCHEMA_VERSION`（整数）＝ IndexedDB のデータベースのバージョン番号（2系統にしない）。`meta.schemaVersion` は確認用の写し。
- 移行は `onupgradeneeded` の versionchange トランザクションの中で、ストア追加とレコード変換を行う。このトランザクションは途中で失敗すると全体が取り消されるため、半端な状態が残らない。レコード変換は `migrations[n]: (record, store) => record` の純粋関数（バックアップファイルの移行と共通）。
- 移行の前に、旧データを書き出し形式で `localStorage` ではなく IndexedDB の別データベース `manabi-no-niwa-premigrate` に1世代だけ退避する（容量不足なら退避なしで続行し、保護者画面に記録）。
- 古い版のアプリで新しいデータベースを開いた場合（`VersionError`）: 子供画面は「おうち」だけの案内、保護者画面に「新しい版のデータです。アプリを更新してください」。データは変更しない。
- 他のタブがアップグレードを妨げる場合（`blocked`）／自分が妨げる側（`versionchange`）: 自分の接続を閉じて「再読み込みしてください」を表示。
- 新版で開いた古いバックアップファイルの読み込みも同じ移行関数を通す。新しすぎる版のファイルは拒否する。

### 5.5 書き出し・読み込み

書き出し形式:
```json
{
  "format": "manabi-no-niwa-backup",
  "schemaVersion": 1,
  "appVersion": "1.0.0",
  "exportedAt": "2026-10-24T10:00:00.000Z",
  "scope": "all" | "profile",
  "data": { "profiles": [], "settings": [], "progress": [], "attempts": [],
            "rounds": [], "works": [], "memos": [], "favorites": [] }
}
```
- 書き出し: Blob を作り `<a download>` で保存（ファイル名 `manabi-backup-YYYYMMDD-HHmm.json`）。
- 読み込み: `<input type=file accept=.json>` → サイズ ≤ 20MB → JSON 解析 → `format` → `schemaVersion ≤ 現行` → 各レコードの型検証（手書きの検証関数）→ 移行 → 確認画面（何が何件入るか、名前）→ 実行。
  - 既定「プロフィールとして ついか」: 読み込んだプロフィールに新しいIDを振り、関連レコードのIDも付け替える。同名なら「（2）」を付ける。
  - 「すべて おきかえ」: 確認の文字入力（「おきかえ」と入力）＋直前に現在のデータを自動で書き出す。

## 6. 各モードの判定・生成の構造

各モードは次のファイル構成を守る（NF-04）。

```
src/modes/<mode>/
  content.ts      教材データ（段階ごとの素材・盤面・問題の種）
  logic.ts        生成（seed → 問題）・判定・ヒント選択（純粋関数）
  logic.test.ts   単体テスト（複数seed）
  voice.ts        このモードの音声台本
  <Mode>.tsx      UI（content と logic を呼ぶだけ）
  *.module.css    モード固有のスタイル（トークンを使う）
```

### 6.1 生成問題の検証
- `generate(level, seed, index)` は決定的。テストでは seed 1..200 × 各段階で生成し、次を確認: 正解が存在し一意（複数解を認める課題は解の集合が空でない）、選択肢が重複しない、段階の範囲（数の上限、選択肢数など）を満たす、同じ回の中で同一問題が重複しない。
- 失敗時はテスト名に seed と段階を出す（再現可能）。

### 6.2 みちをつくろう の盤面規則（M7-05）
- 盤面は格子（列×行）。各マスは `empty` / `tile(kind, rot)` / `fixed(tile)` / `rock`（障害物）/ `start(dir)` / `goal(dirs)`。
- スタートは開口が1方向（盤面データで指定）。ゴールは開口の方向を盤面データで指定（1〜4方向）。
- 道具: まっすぐ（初期の向き=よこ）、まがりかど（初期の向き=右と下）、けす。置いた道をタップすると、選んでいる道具に関係なく90°回る（「けす」を選んでいるときだけ消える）。固定の道・いわ・スタート・ゴールは回らない。
- タイル: `straight`（2向き）、`corner`（4向き）、`tee`（分かれ道、4向き、R3 で固定タイルとして出る）。各タイルは上・右・下・左の開口を持つ。回転は時計回り90°。
- つながり: 隣り合う2マスが互いに向き合う開口を持つときだけ接続（片側だけ開いているのはつながらない）。
- 盤面の端: 端に向いた開口はどこにもつながらない（行き止まり）。
- 分岐: 分かれ道ではどちらに進んでもよい。動物は「スタートからゴールへの経路があればその1つ（幅優先探索の最短）」を進む。
- 循環: 経路探索は訪問済みのマスに戻らない。輪になった道があっても止まらずに探索が終わる。
- 経路がない場合: スタートから到達できるマスのうち、ゴールに最も近い（マンハッタン距離）マスまで最短で進み、そこで止まって「？」の印と、そのマスの開口のうち相手とつながっていない向きを点線で示す。同点は (1) スタートからの経路が長い方 (2) 行が小さい方 (3) 列が小さい方 の順で決める（決定的）。
- ヒント1は「うさぎが とまった ところから つづきを つくろう」。
- 正解判定: スタートとゴールが接続していること（どの経路でもよい。M7-04）。
- 教材の検証: 各盤面に「参考解」を持たせ、テストで ①初期状態ではつながっていない ②参考解でつながる ③参考解は置けるマス（empty）だけを使う ④障害物の上に置かない を確認。

### 6.3 なぞりの判定（M8）
- 座標系: お手本は 0〜1000 の正方形座標。表示時に描画領域へ縮尺。判定は正方形座標に戻して行う。
- お手本の画（ストローク）は等間隔の点列（約10単位ごと）。
- 判定幅 r（正方形座標で）: ひろい 90 / ふつう 65 / せまい 45。入力種別ごとに設定（初期値は指・ペン・マウスすべて「ひろい」。Linux の Firefox がタッチをマウスとして報告する場合があるため）。
- 入力の前処理: `pointermove` の `getCoalescedEvents()` を使って点を集め、線分として扱い、5単位ごとに補間した点列にする（速い指の動きで点がまばらになっても判定が崩れない）。
- **順序つき追跡（近道・塗りつぶし・小さなループ対策の中心）**:
  - 各画に「進み位置」k（お手本の点の番号）を持つ。最初は 0。
  - 入力の線は、始まりが「今の進み位置」のお手本の点から 1.5r 以内のときだけ追跡に使う（最初は始点、離して再開するときは止まった所から）。それ以外で始まった線は描画だけ残し、判定には使わない（ヒント「みどりの まるから」／「とまった ところから」）。
  - 線の点を順にたどり、各点について、お手本の点 k+1 〜 (kから弧長で 1.2r 先まで) のうち入力点から r 以内にある最も先の点まで k を進める。弧長の先読みを 1.2r に限るため、曲線の内側を直線で横切る近道や、「る・ろ・の」の小さなループの中心を通る線では、ループの反対側の点が先読みの範囲外になり k が進まない。
  - 閉じた形（まる等）も、点の番号で進むため始点＝終点でも曖昧にならない。
  - 迷路（T3）は通路の中心線をお手本とし、r を通路の半分の幅に固定する（設定の判定幅は使わない）。
- 1画の完成条件: 進み位置 k がお手本の最後の点（またはその手前、弧長で r/2 以内）に達した。
- 塗りつぶし対策: 1本の線の点のうち 1.5r より外にある割合が 40% を超える線は、追跡に使わない。
- 点だけの入力: 線の長さが r/2 未満の線は無視する。
- 逆向き: 終点側から書いた線は始まりが進み位置の近くにないため追跡に使わない（声かけ「みどりの まるから かこう」）。
- 再開: 指を離しても k は保持（M8-06）。「ひとつ もどす」は直前の線を取り消し、その画の k を残りの線から再計算する。
- 複数の画: 今の画（番号つき）だけを判定。完成したら次の画の始点を示す。
- 入力の途切れ（短い線が5本以上続く）は `operationIssue` として記録（PA-09）。
- 判定の単体テスト（実装より先に作る）: 正しいなぞり／r 以内のはみ出し／直線の近道／ループの中心を横切る線／点を打つだけ／往復の塗りつぶし／逆向き／途中で離して再開／速い動き（点の間隔 40 単位）／閉じた形。

旧方式（参考・不採用）:
  1. 被覆率: お手本の点のうち、入力点から r 以内にあるものの割合 ≥ 0.85
  2. 終点到達: お手本の終点から r 以内に入力点がある
  3. 向き: 入力の各線について、最も近いお手本上の位置（0〜1）の進み方が全体として前向き（始めの1/3の平均より終わりの1/3の平均が大きい）。逆向きの線は被覆に数えない
  4. 近道・塗りつぶし対策: 被覆はお手本の点ごとに「近くを通った」ことを数えるため、直線で近道するとお手本の曲がった部分が覆われず条件1を満たさない。さらに、入力の総延長がお手本の長さの3倍を超え、かつ入力点の50%以上がお手本から 2r より遠い場合は完成にしない
  5. 点だけの入力: 総延長が r 未満の線は無視
  （被覆率だけの方式は、管の中の往復や小さなループの近道を防げないため、設計レビューで不採用とした）

### 6.4 かたちの吸着と回転（M4）
- ピースは `{ shape, size, rot }`。置き場所（スロット）は `{ shape, size, rot, x, y }`。
- 形ごとの回転対称の次数: まる=∞、しかく=4、ながしかく=2、せいさんかく=3（90°刻みでは一致しない→K4では二等辺直角三角形を使用）、ちょっかくさんかく=1、はんえん=1、ほし（5角）は90°刻みでは一致しない→回転問題に使わない。
- 一致判定: 形と大きさが同じで、`(piece.rot - slot.rot) mod 360` が対称の角度の倍数。
- 吸着: タップ位置から中心距離が盤面幅の20%以内の空きスロットのうち、選んだピースと一致するものの中で最も近いものに吸着。一致するスロットがなければピースは手元に戻り、ヒント。距離が同じ（差が1%未満）なら、番号の小さいスロット。
- 同じ形・大きさのピース（しかく2つ等）はどちらのスロットに入れてもよい。
- K5 は盤面に外形（完成した絵の影）だけを描き、内側の線は描かない。見本（完成図の小さな絵）を盤面の横に常に表示する。吸着の規則は同じ。
- K1〜K3, K5 はピースが最初から正しい向き。K4 は1つ以上のピースが回転を要する。

## 7. オフライン・キャッシュ・更新

### 7.1 方式
- ビルド時に Vite プラグイン（`scripts/vite-plugin-precache.ts`）が、`dist/` の全ファイル（index.html, JS, CSS, フォント, 音声, アイコン, manifest）の一覧とハッシュから **版ID**（内容ハッシュ）を作り、`dist/sw.js` に埋め込む。
- `sw.js` の install: キャッシュ `mnw-<版ID>` に一覧を全件取得。進行状況を `postMessage` で画面に送る（OF-02）。1件でも失敗したら install 失敗（中途半端な版を使わない）。
- fetch: 同一オリジンの GET は、まず現在の版のキャッシュから返す（キャッシュ優先）。ナビゲーションは `index.html` を返す。キャッシュにないものはネットワーク。
- activate: 現在と**直前の版**以外のキャッシュ `mnw-*` を削除。fetch は現在の版のキャッシュになければ直前の版のキャッシュも探す（別のタブで旧版の画面が開いたまま新版に切り替わっても、旧画面が遅延読み込みする部品が見つかるように）。`clients.claim()` は使わない。
- 部品の遅延読み込みに失敗した場合は、子供画面に「おうち」だけの画面を出し、保護者向けに「再読み込みしてください」を表示。

### 7.2 更新（OF-04, OF-05）
- 新しい `sw.js` が見つかると、裏で新版キャッシュを作る（旧版は動いたまま）。
- 準備ができると waiting 状態になり、保護者画面に「あたらしい ばーじょんが あります」と「こうしんする」ボタン。押すと `SKIP_WAITING` → 再読み込み。
- 押さなくても、全てのタブを閉じて次に開いたときに新版に切り替わる（ブラウザ標準の動作）。
- 1つの版のファイルは1つのキャッシュにまとまっているため、旧画面と新教材が混ざらない。
- 学習データは IndexedDB にあり、キャッシュの入れ替えで消えない。新版の初回起動時に移行（5.4）。

### 7.3 ブラウザごとの扱い
- Service Worker は `http://127.0.0.1` を安全なオリジンとして扱うため、ローカル配信で動作する（Chromium・Firefox 共通の仕様。実機で確認する）。
- `file://` では動かない（README に明記）。
- PWA としてのインストール（アプリ窓）は Chromium 系で可能。Firefox のデスクトップ版は通常ブラウザのタブで使い、オフラインは Service Worker で成立する。
- **オリジン（`http://127.0.0.1:8765`）を変えるとデータが別扱いになる**ため、ポート番号は固定（README に明記）。

## 8. ローカル配信と導入（deploy/zorin）

| ファイル | 役割 |
|---|---|
| `serve.py` | Python 3 標準ライブラリだけで動く静的配信。`127.0.0.1:8765` に限定。MIME を正しく返し、`index.html`・`sw.js` は `no-cache`、ハッシュ付き資産は長期キャッシュ |
| `manabi.sh` | 起動用。配信が動いていなければ裏で起動し、ブラウザ（Chromium があれば `--app` 窓、なければ Firefox）で開く |
| `install.sh` | 配布 zip の中身を `~/.local/share/manabi-no-niwa/` に配置し、`.desktop`（アプリ一覧とデスクトップ）を作る。`--autostart` を付けたときだけ systemd ユーザー単位のサービスを登録。実行前に何をするか表示して確認 |
| `uninstall.sh` | 上記の取り消し（学習データはブラウザ内にあるため消えないことを表示） |
| `manabi-no-niwa.service` | systemd --user 用の単位ファイル |

- Zorin OS は Python 3 を標準で含む（実機で `python3 --version` を確認する手順を README に記載）。
- 更新: 新しい zip を展開して `install.sh` を再実行 → 次回起動時に Service Worker が新版を検出。

## 9. 状態の扱いと不具合対策

- 二重遷移防止: ルート変更は `navigate()` を経由し、遷移中フラグで連打を無視。
- 二重回答防止: `useAnswerLock`（4.2）。
- 音声の競合: `AudioEngine` は常に1列だけ再生（5.2）。
- 中断: モードは `draft.save()` を各問題の確定時に呼ぶ。`おうち` で離れた場合、次回そのモードを開くと「つづきから／はじめから」（絵の札2枚）。
- 再読み込み: 問題の途中の状態は draft から復元（問題の seed と番号から再生成できるため、問題内容は同じ）。
- 利用時間: `rounds` の当日の合計から算出。到達は「区切り」でのみ表示（CX-04, CX-07）。

## 10. テスト用の仕組み

- `localStorage['mnw:test'] = '1'` のときだけ、`session.expose()` が `window.__mnw` に現在の問題データを置く（E2E が正解を計算するため）。通常利用時は何も置かない。
- `?seed=<n>` で最初の回の seed を固定（テストの再現用）。

## 11. セキュリティとプライバシー

- 外部への通信コードを持たない。Content-Security-Policy（`default-src 'self'`; 画像は `self data: blob:`）を `index.html` の meta で設定。
- 読み込むファイルは JSON として解析し、文字列は React でエスケープして表示（HTML として解釈しない）。
- 保護者の暗証番号は SHA-256 のハッシュで保存（強固な保護ではない旨を明記）。
