## D. エンジンへの要望（教材担当から。未対応）
教材ではいずれも図（svg）や別のエンジンで代用している。
- **number**: わり算の筆算で商が2けた以上（作業領域に入らない）、小数の筆算、「指定した分母の形で答える」判定、式の図の分数の中の空欄
- **graph**: 関数（x–y）のグラフ・反比例の曲線、柱状グラフ、ドットプロット、帯グラフを複数本、区画に%、表の空欄セル、数を答える欄の誤答の照合を値で（今は文字列）、二つの観点の表、数の欄の長さ（10字）
- **geometry**: コンパスの作図、合同の作図の誤概念の推定、作図で点の名前（O など）を出す
- **figure**: 角柱・円柱の見取図と展開図、回路と方位の部品、折れ線の点の強調、svg の最小の大きさ
- **numberline**: 2本の数直線（比例の対応）
- **RichText**: 分数 `[[ ]]` の中に式
- **map**: 世界地図、竹島・尖閣諸島の拡大図（今は全国図に小さすぎて描かれない。5年の領土は文と選択肢で扱う）、記号「避難場所」、地図記号を選択肢の図に使う
- **order**: 縦並びで5枚以上。**年表の帯**の図
- **experiment**: 働かない固定条件を表示しない、reach の誤概念の自動推定、表の結果に記号
- **program**: 複数の世界での正しさの検査（`worlds[]`）、任意の角度の描画（タートル）、特定の札の使用を必須にする、自動ヒント③が答えまで言う場合がある（prog-g16 kit）
- **trace**: 英字の4線を盤に出し、字の位置を中央に寄せない指定
- **clock**: 秒
- **choice・sort・match の配置**: 長いラベルの折り返し、sort の箱の小型化、match のラベルの1行固定（生活・プログラミングで問題を短くして代用）
- **音声**: `en/` の英語の音声が無いとき日本語の声で読む（en-US で読むか無音に）、日本語の読み上げ文の中の英字を分ける
- **buildRound**: 生成型の単元の `source.items`（手作りの問題）を出題しない
- **vitest**: 絵の自動読み込み（import.meta.glob）に新しいファイルが入らないことがある（変換キャッシュ）

## E. 教材の内容で人の確認が要るもの
レビュー（小1〜小4の算数・国語は Fable の独立レビュー、それ以外は Opus。Opus は見つけた担当が修正しており独立ではない）で直しきれなかった・確信が持てなかったもの。各パックの `review*.test.ts` が直した点の再発を防ぐ。
- **全体**: 学習指導要領の項番号（各単元の basis）は原文と照合していない。学年の割り当てのうち本アプリの案（`gradeIsAppProposal`）。
- **国語**: 送り仮名の通則の分類（明るい・少ない・冷たい・幸せ・温かい）、敬語「参る」を謙譲語として扱う、和語・漢語の分け方（擬音語）、古典の年代（徒然草）・春暁の書き下し、同音異義（競走/競争）、読点の問題の一部、「ねずみの およめいり」が教科書の定番でないか、小4の読解本文の題材の重なり（ペンギン・メダカ・ミツバチ）
- **漢字**: 中学校の読みかどうか（化ける・覚める・素直の「す」・興す・就く・頂・河・率・富む・負う）、形の似た字の表（自動の補完が多い）、はじめの画の表、殺風景・殺虫・皇居・天皇陛下など残した語
- **算数**: 誤概念の推定（九九を1つずれて思い出す等）の妥当性、単位の感覚の値、通分は最小公倍数だけを正解（かけた分母は誤り）、帯分数・仮分数の慣習、「仮の商」の立て方、1m² の目安、自作の svg の図の見え方（角柱の見取図・展開図・2本の数直線・相似の三角形など。画面で見ていない）
- **理科**: 影の方位の単純化（午前9時は「西のほう」）、方位磁針の印、燃焼・溶解度・発芽の値（「れい」）、台風の進路の言い方、けん流計の言い方
- **社会**: 地図記号27種の形を国土地理院の記号表と照合していない（病院・消防署・城あと・老人ホームが特に不確か）、工場の記号の扱い、日本の範囲の数値、大仏・伊能忠敬・遠洋漁業などの説明、雨温図（典型の形に似せた例）、北方領土を北海道に含めた判断
- **英語**: Kokoro の読み（文字の名前の連続・o'clock・序数）、まぎらわしい選択肢（teen/ty、似た綴り）、cup の訳「コップ」、山の絵が木
- **生活・プログラミング**: 都道府県の○×の表、季節・安全のきまりの例、画面の高さの見積もり（746×630 でしか見ていない。いくつかの問題が3〜4u はみ出る）
- **軽微の残り**: 小1〜小4の独立レビューの全文は docs/expansion/reviews/content-review-g1-g2.md・content-review-g3-g4.md（「軽微」の多くと一部の「中」は未対応のまま）。Opus のレビュー（小5・小6・理科・社会・英語・生活・プログラミング・漢字・幼児・小2算数）の「直していないもの」は、主なものを上に挙げた。全文はリポジトリに残っていない

## G. 音声の聞き取りやすさの改善（未対応。依頼者から「自然でなく聞き取りにくい部分がある」）
いまの日本語の音声は Open JTalk（pyopenjtalk-plus）＋「Mei」HTS Voice で、抑揚が平板になりやすい。英語は Kokoro-82M（af_heart）。どれも開発の PC であらかじめ作り、配布物に入れる（実行時の音声合成・通信はしない。この方針は変えない）。

**候補（声の作り方を変える）**
| 候補 | 自然さ | ライセンス・注意 | 作る手間 |
|---|---|---|---|
| Kokoro-82M の日本語の声（jf_* など） | 中 | Apache-2.0。英語で使っている仕組み（scripts/voice/generate_en.py）を流用できる | 小。まず試す候補 |
| Qwen3-TTS（Qwen チーム、2026年1月公開。0.6B・1.7B） | 高（見込み） | Apache-2.0（商用・配布可）。日本語を含む10言語。文章で声の雰囲気を指定できる。参照音声から声をまねる機能は、記事によって有無の記載が分かれ、未確認 | 中〜大。言語モデル型で GPU の無い PC では遅い（約11万本で数日の可能性。0.6B から試す）。声を1つに固定する（用意された話者か参照音声）、読み飛ばし・繰り返しを長さなどで自動検査する、ひらがなの読みを渡す、が必要 |
| VOICEVOX（エンジンはオープンソース） | 高 | 声（キャラクター）ごとの利用規約。多くは「VOICEVOX:〇〇」のクレジット表記が必要。子供向け教材での利用・配布の可否を声ごとに確認 | 中。CPU で全約11万本は十数時間の見込み |
| Style-Bert-VITS2 / AivisSpeech の公開モデル | 高 | モデルごとのライセンス（CC BY-SA 等、利用条件がさまざま） | 中〜大 |
| クラウドの音声合成（Google・Azure 等） | 最高 | 従量課金（依頼者の承認が要る）。作った音声を配布してよいか規約の確認が要る | 小（費用が発生） |

**声を変えずにできる改善**
- 読み・アクセントの誤りを辞書（ユーザー辞書）に登録する。教材の《よみ》の見直し（g4〜g6 算数は辞書で自動付与。scripts の ruby.ts）
- 話速・高さの調整（scripts/voice/generate.py の設定）。長い文に読点を入れて区切る
- 数の読みの助数詞の音の変化（3本＝さんぼん、6分＝ろっぷん 等。src/voice/speech.ts・src/text/yomi.ts）

**依頼者の方針（2026-10-24）**
- 声の作り方を **Qwen3-TTS** か **Style-Bert-VITS2 / AivisSpeech の公開モデル**に置き換える（比べて決める）。
- 全部でなくてもよいが、**少なくとも「読み上げた音声を元に答えたり操作したりする」所は必ず変える**。範囲は次のとおり（本数は 2.0.0 の台本 voice/packs/*.json の数）。
  1. 聞いて答える問題: エンジン listen の問題（全学年。音・ことば・お話を聞いて選ぶ）と、聞き取りの単元（g1.ja.listen など）
  2. 幼児の音声すべて: p23 623・p4 2,170・p5 2,900 本と、初期版9モードの音声（public/audio 直下 約1,300本。scripts/voice の台本 voice/script.json）。字が読めない前提で、指示を聞いて操作するため
  3. 小1・小2の問題文（自動で読み上げる前提）: g1-ja 3,594・g1-math 3,304・g2-ja 2,184・g2-math 2,702・life-g12 1,026・kanji-g12 6,010 本のうち問題文の部分（ヒント・解説は任意の読み上げ）
- それ以外（小3以上の問題文・ヒント・解説など、「きく」ボタンで任意に聞くもの）は今の声のままでもよい。ただし同じ問題の中で声が混ざって不自然なら、単元ごとまとめて置き換える。数の部品（num）は、上の範囲で使う数の読みも同じ声にそろえる。
- 英語（Kokoro）は今回の指摘の対象外（聞き取りの問題なので、聞き比べで問題があれば同様に検討）。
- 実装の要点: 台本に「声の種類」（新しい声／今の声）を持たせ、scripts/voice に新しい生成スクリプトを足す。配布 zip に新しい声のライセンス表記（licenses/・README）。モデルのダウンロードは依頼者の了承を得てから（ファイル名・入手元・大きさを示す）。

**進め方の案**
1. 聞き取りにくい文を20〜30本選ぶ（依頼者に画面・文を挙げてもらう。長い説明文、数と助数詞、漢字の読み、英字まじり を含める）
2. いまの音声と候補（Kokoro 日本語、Qwen3-TTS、VOICEVOX の声 2〜3種 など）で作って聞き比べる（子供にも聞いてもらう）。あわせて1本あたりの生成時間を測り、全約11万本にかかる時間を見積もる
3. 決めたら、ライセンスを licenses/ と README の「素材とライセンス」に記録し、全パックを作り直す（台本は voice/packs/*.json、作り方は README「音声の作り直し・差し替え」と docs/assets-pipeline.md）。配布 zip の大きさが変わるので scripts/package-release.ts の分け方も確かめる
