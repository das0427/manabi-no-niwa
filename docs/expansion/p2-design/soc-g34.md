## 0. 実装担当へ（共通の決まり）

### 0.1 置き場所・書き方
- 新しいファイル: `src/packs/soc-g34/safety.ts`（g3.soc.safety）、`src/packs/soc-g34/tradition.ts`（g4.soc.tradition）。
- `src/packs/soc-g34/index.ts` の `units` の末尾に `safety`・`tradition` を足し、`ALLOW` に `'g3.soc.safety': safetyAllow`、`'g4.soc.tradition': traditionAllow` を足す。
- 書き方は同じパックの **`disaster.ts`（g4.soc.disaster）にそろえる**: `util.ts` の `baseSoc`・`choiceItem`・`multiItem`・`orderItem`・`matchItem`・`sortItem`・`fillItem`・`readingItem`・`table`・`textFig` を使い、手作りの `items` の一覧（`source: { kind: 'items', items }`）。同一性キーは **問題の id**（`util.ts` の各関数が `identity: s.id` を入れる）。
- 単元の共通の項目: `...baseSoc(id, stage)` のあとで **`priority: 'P2'` を上書き**する（baseSoc の既定は 'P1'）。`kind: 'inquiry'`、`status: 'ready'`、`review` は baseSoc の `'objective'`（SR観）、`icon` は baseSoc の `'subj-shakai'`。
- **ファイルの先頭のコメント**は disaster.ts と同じ形（単元ID・題・指導要領の該当・到達項目と別例の形・同一性キー・架空の例であること）。
- 文の漢字はすべて `漢字《よみ》`。小3以上なので **分かち書きしない**（`review-soc34.test.ts` の WAKACHI 検査。日本語の字と字の間に空白を入れない）。
- 選択肢は **4つまで**（ux-by-age。`soc-g34.test.ts` の MAX_CHOICES）。order の縦並び（column）は **4枚まで**。match は1段 **6枚まで**。sort は箱2〜4・カード2〜10。

### 0.3 119番・110番の文の決まり（`review-soc34.test.ts` で落ちないため）
検査は **1つの文字列ごと**に、
- 「119」と「警察・けいさつ・交番・こうばん」が同じ文字列にあるのに「110」が無い → 誤り
- 「110」と「消防・しょうぼう・救急・きゅうきゅう」が同じ文字列にあるのに「119」が無い → 誤り

を見る。下の文はこの決まりに合わせて書いてある。**言い換えるときも、1つの文（問題文・選択肢・ヒント・解説・カード・表のます）に「119」と「警察／交番」、「110」と「消防／救急」を片方だけ入れない**。

### 0.4 ヒントの決まり
- 3段（①何を見るか ②図・本文の一部・途中まで ③最後の一手を残す）。**正解の選択肢の文（ふりがなを除いた文）をそのまま含めない**（`review-soc34.test.ts`: 2字以上の正答がヒントに含まれると誤り。fill の答えも同じ）。下のヒントは確認済み。言い換えるときに正答の語（例「通信指令室」「11年」）をヒントに入れないこと。

### 0.5 学年より上の字（ALLOW）
下の各単元の「ALLOW」の表のとおり（全文を検査し、ここに無い学年より上の字は使っていない）。文を直すときに新しい字を足さない。

### 0.6 絵
- 新しい絵は **要らない**（`src/illust/content/soc-g34.tsx` は作らない）。
- 既存の絵を使う: `life-firestation`（しょうぼうしょ）、`life-police`（こうばん）、`life-hospital`（びょういん）（`src/illust/content/life-g12.tsx`。登録済みなので id の文字列だけで使える。import しない）。
