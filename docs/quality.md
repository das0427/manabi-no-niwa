# 品質の確かめ方（quality.md）

このアプリで、何をどう確かめたか、その数、確かめていないことを書きます。守っている約束は2つです。実際の数を書くこと。確かめていないことを書くこと。

- 対象は 2.1.0 です。テストや検査の数は、公開の前の確認（{{QA:検査の日}}）の結果です。
- 実機（Zorin OS）と子供での確認は、まだしていません。学習の効果も検証していません。
- 検査の多くは機械が測ったものです。人が画面を見たり音を聞いたりして確かめたものではありません。AI が人の代わりに読んだものも、実際の保護者や子供の反応ではありません（[ai-roles.md](ai-roles.md)）。

## 検査の種類と、見ているもの

| 検査 | 実行 | 見ているもの | 見ていないもの |

| 単体テスト | `npm test`（Vitest） | 判定・問題の生成・進み具合・保存・復習などの関数、画面の部品、配布の道具（`scripts/release-lib.ts`）。問題の生成は乱数の種を変えて繰り返します | 実際のブラウザでの見え方と操作 |
| 教材の自動検査 | 単体テストの中と `npm run curriculum:report` | 単元ごとに、問題の量・網羅・ヒントの段数・誤概念・よみのない漢字・選択肢の数・学年より上の漢字・どの問題にも当てはまる誤答の割合（20%以下）・音声がそろうこと。種を1000通りで検査します | 問題が教えたいことに合っているか、事実が正しいか |
| DESINGN.md の自動検査 | `npm run check:design` | 色の名前と値が表と合うこと。文字は 4.5:1、図形は 3:1 の明るさの差があること | 色の見分けやすさを人の目で見ること |

## 検査の限界
- 機械の検査は、測れるものだけを見ます。字がはみ出すかは測れても、読みやすいか、子供に分かるかは測れません。
- 検査を作った AI と、直した AI は、同じ系統です。検査の見落としは、検査の検査（probe）と、点検での再現で減らしましたが、無くなってはいません。
- 検査の結果は、検査を実行した時点のコードのものです。公開のあとに変わった所は、確かめ直しが要ります。
- 判定役の比較は、新しい文が読みやすいかを AI が選んだ結果です。事実の正しさは別に確かめています。

## 再現のしかた

```bash
npm run check          # 型・lint・書式
npm test               # 単体テスト
npm run check:design   # DESINGN.md の自動検査
npm run check:audio    # 台本と音声
npm run check:packs    # 教材パックの分離（ビルドのあと）
npm run e2e            # E2E（Chromium・Firefox）
npm run e2e:update     # 自動更新の通し
npm run test:py        # Python のテスト（Linux は test:py:sh）
npm run check:text-layout       # 文字の配置の検査（全単元で1〜2時間かかります）
npm run check:app-layout        # アプリの画面の検査
npm run curriculum:report       # 単元の充足の報告
```

検査の計画は [test-plan.md](test-plan.md)、実機で確かめる項目は [device-checklist.md](device-checklist.md)、引き継ぎは [expansion/handover.md](expansion/handover.md) です。
