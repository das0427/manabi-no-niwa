# 要件定義書（requirements.md）

アプリ名（仮）: **まなびのにわ**（manabi-no-niwa）
版: 1.0（2026-10-24） / 責任: Opus（統括）

この文書は「何を満たせば完成か」を定める。画面や実装の詳細は architecture.md、学習の段階は learning-design.md、見た目の規約は DESINGN.md、検証方法は test-plan.md に分ける。

---

## 1. 目的

遊びながら、数・文字・分類・図形・記憶・比較・試行錯誤・運筆に親しめる環境をつくる。
最大化しないもの: 利用時間、正答数、連続日数。
重視すること:

| ID | 重視すること | このアプリでの具体 |
|---|---|---|
| GL-01 | 自分で始められる | 文字が読めなくても、絵と音声だけでホーム→遊び→終わりまで進める |
| GL-02 | 考えて試せる | 数える・分ける・向きを変える・つなぐ等、操作そのものが考える過程になる |
| GL-03 | 失敗しても続けられる | 誤答の罰（ブザー・減点・残機・強制やり直し）がない。短いヒントが出る |
| GL-04 | 納得して終われる | 3〜5問／1作品の短い区切りと、行ったことを言葉にする完了画面 |
| GL-05 | また遊びたくなる | 選べる・できた実感・作品が残る。ランダム報酬や連続日数では釣らない |

## 2. 利用者と利用場面

| 利用者 | 前提 |
|---|---|
| 子供（主） | 4歳の日本語話者。ひらがなを十分に読めない前提。メール・パスワード入力はしない |
| 保護者 | 設定・記録の確認・必要な手助け。端末とブラウザの基本操作ができる |
| きょうだい | 同じ端末を使う別の子供。プロフィールを分ける |

利用場面:
- 家庭のリビングで、保護者が近くにいる状態で子供が1回5〜10分程度遊ぶ。
- ネットにつながっていない時間も使う（日常利用はオフライン）。
- 子供はノートPCをタブレットのように指で操作する。保護者はタッチパッド・マウスも使う。

## 4. 基本条件

| ID | 要件 | 受入条件 |
|---|---|---|
| BC-01 | 画面表示・音声は日本語 | 子供画面に英語ラベルがない（自動検査） |
| BC-02 | 実行時に外部LLM・従量課金APIを使わない | ビルド成果物に外部APIへの通信コードがない。オフラインで全機能が動く |
| BC-03 | 広告・外部トラッキング・必須アカウントなし | 外部ドメインへの通信がない（E2Eで通信を監視） |
| BC-04 | 教材・画像・音声・フォントを同梱しオフラインで動く | 初回準備後、通信を遮断して全9モードを開始〜完了できる（E2E） |
| BC-05 | 通信要件を区別して説明 | README に「導入時」「初回準備時」「日常利用時」「更新時」の通信を分けて記載 |
| BC-06 | 履歴・設定・作品は端末内に保存 | IndexedDB に保存。外部送信しない |
| BC-07 | エクスポート／インポート | JSONファイルで書き出し・読み込みができる（DA-04〜07） |

## 6. 機能要件：共通

### 6.1 ホーム（HM）

| ID | 要件 | 受入条件 |
|---|---|---|
| HM-01 | 全9モードを選べる | ホームで9モードすべての札が常に見え、1タップでそのモードに入れる（遊び方の選択・つづきからの確認を除く） |
| HM-02 | 大きなイラストと短い日本語名 | 各モードに固有のイラストと、ひらがな名。タップで名前を読み上げる |
| HM-03 | 「きょうの おすすめ」2〜3件 | 説明可能な規則で選ぶ。他モードはロックしない |
| HM-04 | 「すきな あそび」 | 子供が完了画面で「すき」にしたモードの札にハートの印が付く。並び順は変えない（いつも同じ場所） |
| HM-05 | 保護者が表示を変えられる | 「ぜんぶ」「えらんだ ものだけ」を切り替え、表示モードを選べる |
| HM-06 | 小さな画面に詰め込まない | 1280×720（150%表示）でも、主操作の目標寸法（OP-03）を満たし、横スクロールが出ない |

### 6.2 音声（VO）

| ID | 要件 | 受入条件 |
|---|---|---|
| VO-01 | 問題・説明・ヒント・結果に音声 | 子供画面で表示される指示文すべてに音声キーがある（自動検査） |
| VO-02 | いつでも「もういちど きく」 | 各問題画面に常時表示。押すと現在の問題文を最初から再生 |
| VO-03 | 重複再生しない | 新しい再生は前の再生を止めてから始める（単体テスト） |
| VO-04 | 画面移動・やり直し・バックグラウンドで停止 | 画面遷移時、タブ非表示時に停止（E2E） |
| VO-05 | 自動再生制約に対応 | 起動時の「はじめる」タップで音声を有効化 |
| VO-06 | 再生中が分かる | 再生中はスピーカー表示が動き、操作は受け付ける（音声待ちで固まらない） |
| VO-07 | OSの読み上げだけに依存しない | 音声は同梱の録音（生成）ファイルを使う。ファイルがない場合のみOSの日本語読み上げに切り替え、どちらもない場合は保護者画面と画面上に「おとが でません」を示す |
| VO-08 | 台本と生成手順を残す | 全音声の台本（キー・文・読み）と生成スクリプト、ライセンスを記録。実行時は推論サービス不要 |

### 6.3 操作（OP）

| ID | 要件 | 受入条件 |
|---|---|---|
| OP-01 | なぞり以外はタップのみで完結 | 全モードのE2Eをクリック（タップ）のみで完了できる |
| OP-02 | hover・右クリック・ダブルクリック・細かいドラッグを必須にしない | 同上。ドラッグは任意の補助 |
| OP-03 | 主操作の目標寸法 約12〜15mm | 実機の1920px幅=約276mmから換算した寸法を設計値にする（DESINGN.md）。CSS値で実寸は保証しない。実機で測る |
| OP-04 | 隣のボタンとの間に余白 | 主操作どうしの間隔 約4mm以上（設計値） |
| OP-05 | 連打で二重回答・二重遷移・音声競合がない | 判定中・遷移中は入力を受け付けない（単体・E2E） |
| OP-06 | 描画領域だけスクロールとジェスチャーを止める | なぞり・道づくりの盤面で touch-action を制御。他の画面ではブラウザ標準動作を残す |
| OP-07 | 全画面を強制しない | 全画面は保護者設定で任意。解除はいつでもできる |

### 6.4 フィードバック（FB）

| ID | 要件 | 受入条件 |
|---|---|---|
| FB-01 | 誤答ブザー・減点・残機・強制やり直しなし | 誤答時は柔らかい音（または無音）と短い声かけのみ |
| FB-02 | 短い具体的なヒント | 2段階まで（1回目: 注目点を示す／2回目: より具体的に）。答えを直接押させない |
| FB-03 | ヒントを使ったことを記録 | 「自力」「ヒント後」を区別して保存 |
| FB-04 | 観測できた行動に応じた声かけ | 例「ひとつずつ かぞえられたね」（絵をタップして数えた場合のみ）。行動条件のない「よく かんがえたね」を出さない |
| FB-05 | 強調して押させただけの回答を習得にしない | 2回目のヒントで正解候補を示した後の正解は「ヒント後」 |
| FB-06 | 成功演出は短く、課題中の余分な動きを抑える | 成功演出 1.5秒以内。課題中に常時動く装飾なし |
| FB-07 | 動きを減らす設定・音量・効果音設定 | 保護者設定。OSの「視差効果を減らす」設定にも従う |

### 6.5 終わりやすさと継続（CX）

| ID | 要件 | 受入条件 |
|---|---|---|
| CX-01 | モードに合う短い区切り | 1回（ラウンド）= 3〜5問、または1作品。保護者が3/4/5を選べる（初期値4）。盤面型・なぞりは learning-design.md 0.4 の読み替え表に従う |
| CX-02 | いつでも「おわる」 | 全画面に「おうち（ホーム）」ボタン。押すと確認なしでホームへ（作品は自動保存） |
| CX-03 | 中断・再開 | 途中でホームへ戻った回は「つづきから」で再開できる（24時間以内） |
| CX-04 | 利用時間の目安 | 初期値10分（5〜30分、なし を保護者が設定）。到達後、ラウンドの区切りで「きょうは ここまで」を出す |
| CX-05 | 時間は医学的推奨として扱わない | 画面と文書に「目安」と明記 |
| CX-06 | 罰・競争・ランダム報酬なし | 連続日数の途切れ表示、ランキング、ガチャ、ランダム報酬がない |
| CX-07 | 時間到達で作品を捨てない | なぞり中・道づくり中は、その作品を終えるか保存してから区切りを出す |
| CX-08 | がんばりノート（記録帳） | 子供向けに「やったこと」と作品を日付順に絵で振り返れる。点数・順位は出さない |

### 6.6 難易度（AD）

| ID | 要件 | 受入条件 |
|---|---|---|
| AD-01 | モード／学習項目ごとに独立した進度 | 進度は「スキル」単位（例: さんすうは たしざん・ひきざん・わける・しきだけ を分離） |
| AD-02 | 年齢だけでレベルを決めない | 初期段階は全スキル1段階目。保護者が開始段階を選べる |
| AD-03 | 1段階で変える要因は原則1つ | learning-design.md の段階表で、各段階の変更要因を1つ明記。2つ変わる段階は「例外」として理由を明記 |
| AD-04 | 1回の正誤で上下しない | 判定は1回（ラウンド）の終わりだけ。進む: 段階が変わってから10問以上、直近10問中8問以上が自力正解。戻る: 段階が変わってから8問以上、直近6問中 自力正解1問以下かつ（ヒント後＋スキップ）4問以上。見直し後・もういちどやって正解は戻る判定に数えない（単体テスト） |
| AD-05 | 結果の種類を区別 | 自力正解／もういちどやって正解（ヒント1の後）／ヒント後正解（ヒント2の後）／見直し後正解／スキップ／中断。状態表は architecture.md 4.3。操作のとまどい・連打の問題は進度判定から除外 |
| AD-06 | 反応時間で理解度を判断しない | 進度判定に時間を使わない |
| AD-07 | でたらめ連打で習熟扱いにしにくい | 自力正解＝最初の選択で正解。2択の段階は進む条件を10件中9件にする。でたらめに40問答えて誤って進む確率: 2択 7.3%、3択 2.4%（シミュレーション実測。test-plan.md 2.2） |
| AD-08 | 保護者による固定・変更 | スキルごとに「じどう」「こてい（段階指定）」 |
| AD-09 | 調整ルールは説明可能 | 保護者画面に「なぜこの段階か」を文章で表示 |

### 6.7 保護者画面（PA）

| ID | 要件 | 受入条件 |
|---|---|---|
| PA-01 | 誤操作を防ぐ入口 | ホーム右上の小さな鍵ボタンを2秒長押し → 大人向けの計算問題（2桁のたし算）に答える。任意で4桁の暗証番号（塩付きハッシュで保存）。強固な認証ではないと文書化 |
| PA-02 | 設定 | モードごとの難易度、音量、効果音、動きを減らす、利用時間、1回の問題数、ホームの表示、なぞりの判定幅（指・ペン・マウス別。初期値はすべて「ひろい」） |
| PA-03 | 最近取り組んだ内容 | 日付・モード・段階・問題の内容・結果の種類 |
| PA-04 | 自力でできた／ヒントを使った内容 | スキル別に一覧。未実施と不得意を区別して表示 |
| PA-05 | 観察メモ | 日付付きの自由記述 |
| PA-06 | 実生活で試せる遊びの提案 | モードごとに3件以上 |
| PA-07 | 作品一覧 | なぞり作品・道づくり作品を再表示、削除（確認あり） |
| PA-08 | 子供に総合点・偏差値・ランキングを出さない | 子供画面に数値評価がない |
| PA-09 | 操作に困っただけの結果を学力不足として出さない | 「そうさに とまどった」記録（盤面外タップの多発、なぞりの入力途切れ等）を別表示 |
| PA-10 | 複数プロフィール | 追加・名前変更・アイコン変更・削除（明示確認）。記録はプロフィールごとに分離 |
| PA-11 | エクスポート／インポート・記録削除 | DA-04〜08 |
| PA-12 | オフライン準備・更新の状態 | 「オフラインで つかえます」「あたらしい ばーじょんが あります」を表示し、更新は保護者が実行 |

### 6.8 データ（DA）

|---|---|---|
| DA-01 | 端末内保存の方式 | IndexedDB（理由は architecture.md） |
| DA-02 | スキーマとバージョン | `schemaVersion` を持ち、移行関数を順に適用 |

## 7. 機能要件：9モード

共通: 各モードは **学習目標・段階・教材・判定・ヒント・音声・完了画面** を持つ（M*-00）。段階の詳細と変更要因は learning-design.md。

### 【1】おかいものごっこ（M1）

学習目標: 名前を聞いて品物を見つける。1〜5の数を、1つずつ数えてそろえる。2種類の注文をそろえる。

| ID | 要件 |
|---|---|
| M1-01 | 段階: S1 名前を聞いて1つ選ぶ → S2 同じ品物を1〜3個 → S3 同じ品物を1〜5個 → S4 2種類（合計5個まで）。棚は全段階4種 |
| M1-02 | 品物を入れるたびに、その品物の個数を読み上げる（「いち」「に」…） |
| M1-03 | 最後に「ぜんぶで ○こ」を声と数字と絵で示す |
| M1-04 | 追加（棚をタップ）、取り消し（かごの品物をタップ）、注文の聞き直し（ボタン） |
| M1-05 | 注文は絵カード（品物の絵×個数）でも表示する。注文カードは常に見えている（記憶課題と混同しない） |
| M1-06 | 判定: かごの中身（品物と個数の組）が注文と一致。入れた順序は問わない |
| M1-07 | お金の計算は扱わない |
| 教材 | 品物8種（りんご・バナナ・みかん・いちご・にんじん・トマト・パン・たまご）。S4は品物の組28通り×個数 |

### 【2】ひらがな（M2）

学習目標: 音と文字を結び付ける（読む）。言葉の最初の音に気付く。短い言葉を文字で組み立てる。書くことは【8】で扱い、ここでは扱わない。

| ID | 要件 |
|---|---|
| M2-01 | 段階: H1 音を聞いて2択 → H2 音を聞いて3択 → H3 絵と言葉を聞いて最初の文字を2択 → H4 2文字の言葉を作る → H5 3文字の言葉を作る |
| M2-02 | 2択の選択肢は、形の似た字を避ける組から始める（似た字の組は learning-design.md で定義し、H1では出さない） |
| M2-03 | H3〜H5では、絵の名前を必ず音声で言う。絵の名前を知らないことで誤答にならない |
| M2-04 | 文字は教科書体に近いフォント（Klee One）で表示 |
| M2-05 | 同音・表記揺れ・絵と名前の不一致を点検する（点検表を learning-design.md に記載） |
| M2-06 | 文字データは五十音全体（清音46字＋濁音・半濁音）の表を持ち、各字に「収録/未収録」と例語を持つ。拡張は表に例語と絵を足すだけでできる |
| M2-07 | 初期収録: 最初の文字として20字（あ い う え お か き く さ す た と な ね は ひ ふ み も り）。言葉づくり17語。未収録の字は learning-design.md に一覧 |
| M2-08 | 言葉づくりの文字タイルはタップするとその字を読み上げる。選択式（H1〜H3）では誤答時に押した字を読み上げる（音で確かめられる） |

### 【3】なかまわけ（M3）

学習目標: 1つの基準で分ける。基準を切り替えて分け直す。

| ID | 要件 |
|---|---|
| M3-01 | 段階: N1 いろで2つ → N2 しゅるいで2つ → N3 しゅるいで3つ → N4 同じ絵を、しゅるい→いろ の順に分け直す |
| M3-02 | 今の基準を、音声と箱の絵（色見本＋「あか」等の文字／代表の絵）で示す |
| M3-03 | 曖昧な分類、一般知識の引っ掛けを避ける（例: さかな・たまご・トマトの野菜/果物 などは使わない基準にする）。各絵の属性を教材データで固定し、自動検査で一意性を確認 |
| M3-04 | 操作: 絵をタップ→箱をタップ。ドラッグは任意 |
| M3-05 | 違う箱を選んだ場合、絵は元に戻り、ヒント（基準の再提示）が出る |
| 教材 | 色: あか・きいろ・みどり 各4種。種類: どうぶつ・たべもの・のりもの 各6種以上 |

### 【4】かたち・パズル（M4）

学習目標: 形を見分ける。部分を組み合わせて全体をつくる。向きを変えて合わせる。

| ID | 要件 |
|---|---|
| M4-01 | 段階: K1 同じ向きの形合わせ → K2 2〜3ピース → K3 4ピース → K4 回転が必要 → K5 見本だけを見て組み立てる（盤面に内側の線がない） |
| M4-02 | K1〜K3 では回転を必要としない |
| M4-03 | 操作: ピースをタップ→置き場所をタップ。回転は「まわす」ボタン（90°）。ドラッグは任意 |
| M4-04 | 配置は近い置き場所に吸着する |
| M4-05 | 回転対称な形（まる、しかく、ながしかく等）は、同じ形になるすべての向きを正解とする |
| M4-06 | ピースは同じ色にそろえ、形だけで判断する問題を基本にする（色・模様だけで解けない） |

### 【5】おぼえてさがす（M5）

学習目標: 見たものを少しの間おぼえて、さがす。

| ID | 要件 |
|---|---|
| M5-01 | 段階: B1 絵1枚→2択 → B2 絵1枚→3択 → B3 絵2枚→4枚から2枚 → B4 場所（3つの位置のどこにあったか） → B5 順番（2枚） → B6 順番（3枚） |
| M5-02 | 覚える画面では、子供が「おぼえた！」を押して自分で隠す（自動で隠す時間設定は保護者の任意設定） |
| M5-03 | 答える画面に「もういちど みる」。押すと覚える画面に戻る |
| M5-04 | 見直しは「見直し後」として保存し、罰を与えない |
| M5-05 | 記憶量と表示時間を同時に難しくしない（表示時間は段階で変えない） |
| M5-06 | 正解位置に偏りがない。隠した後に答えの手がかり（残像・DOM上の残り）がない |
| M5-07 | 位置記憶では、カードを裏返した状態でも、カード自体に違いがない |
| M5-08 | 記憶力・知能の測定・向上をうたわない |

### 【6】くらべっこ（M6）

学習目標: 大きさ・長さ・数を比べる。同じを見分ける。3つを順に並べる。

| ID | 要件 |
|---|---|
| M6-01 | 段階: P1 おおきさ2択 → P2 ながさ2択 → P3 かず2択 → P4 「おなじ」を含む3択 → P5 3つを順に並べる |
| M6-02 | 初級は差を明確にする（大きさ・長さは1.6倍以上、数は2以上の差） |
| M6-03 | 長さは始点をそろえる（P5の発展でも始点はそろえる） |
| M6-04 | 数を比べるときは物の大きさをそろえる |
| M6-05 | 1問で比べる量は1種類。面積と個数を混ぜない |
| M6-06 | 「おなじ」が正解になる問題と、「おなじ」の選択肢を用意（P4） |
| M6-07 | 表示倍率・配置で正解が逆転しない（2つは同じ座標系・同じ倍率で描画） |
| M6-08 | 「おおきいのは？」「ちいさいのは？」の両方を問う |

### 【7】みちをつくろう（M7）

学習目標: 道をつなぐ順序を考え、試して直す。

| ID | 要件 |
|---|---|
| M7-01 | 段階: R1 欠けた1か所を埋める → R2 直線と曲がり角で2〜3か所 → R3 障害物（いわ）のある盤面 → R4 分かれ道（複数経路）のある盤面 → じゆうに つくる |
| M7-02 | 「しゅっぱつ」で動物が道を進む |
| M7-03 | 途中で止まったら、止まった場所に印を出し、そのまま直せる（盤面はリセットされない） |
| M7-04 | 最短路に限らず、つながっていれば正解。複数経路を認める |
| M7-05 | 盤面の端・回転・分岐・循環の扱いを定義（architecture.md） |
| M7-06 | 全盤面について「解が存在する」「初期状態では未完成」を自動テストで確認 |
| M7-07 | 操作: 道具（まっすぐ／まがりかど／けす）を選んでマスをタップ。置いた道をタップすると90°回る |
| M7-08 | 「じゆうに つくる」の完成結果を作品として保存・再表示できる |
| 教材 | R1〜R4 各8面（計32面） |

### 【8】なぞってあそぼう（M8）

学習目標: 目で線を追いながら手を動かす。始点・終点・向きを意識する。文字の書き順を見る。

| ID | 要件 |
|---|---|
| M8-01 | 段階: T1 太く短い直線 → T2 長い線・ゆるい曲線 → T3 折れ線・形 → T4 かんたんな迷路 → T5 1画のひらがな → T6 2画のひらがな → T7 曲線の多いひらがな |
| M8-02 | 指だけで全段階を遊べる。ペン・マウスも使える |
| M8-03 | 判定幅は入力種別（指・ペン・マウス）ごとに保護者が「ひろい・ふつう・せまい」を選べる |
| M8-04 | 少し外れても線は描ける（描画を止めない） |
| M8-05 | 大幅な近道、点だけの入力、塗りつぶすような入力を完成扱いにしない |
| M8-06 | 指を離して再開でき、最初からやり直しを強制しない。「ひとつ もどす」で直前の1本だけ消せる |
| M8-07 | 文字は書き順のお手本（点が線をたどる動き）を示し、今書く画の始点を示す |
| M8-08 | 運筆用の字形は書き順データ（KanjiVG由来）で、表示用フォントとは別に扱う |
| M8-09 | 指の練習を、鉛筆の持ち方・筆圧の習得と同一視しない（保護者画面に注記） |
| M8-10 | 完成した作品は自動保存し、作品一覧で再表示できる |
| 教材 | T1 6本、T2 6本、T3 6題、T4 4題、T5 6字（し く つ へ の て）、T6 5字（こ い り う ち）、T7 4字（そ る ろ ひ） |

### 【9】さんすう（M9）

学習目標: 具体物と式をつなぐ。合わせる・減る・分けるの意味を絵で確かめる。

| ID | 要件 |
|---|---|
| M9-01 | 式だけから始めない。段階 A 絵を合わせる（合計3まで）→ B 絵と式（B1 合計3まで、B2 合計5まで、B3 たす0）→ C 絵で減る様子と式（C1 3以内、C2 5以内、C3 答え0）→ D 2〜5個を2つに分ける → E 習熟した範囲の式だけ（E1 たしざん、E2 ひきざん） |
| M9-02 | 絵をタップして数え直せる（タップした順に番号が付き、数を読み上げる） |
| M9-03 | E では「えで みる」で具体物を表示できる（使った場合は「見直し後」として記録し、自力正解と区別） |
| M9-04 | 回答は大きな数字の選択肢（3択）。キーボード入力なし |
| M9-05 | 0 の導入: B3 で「たす 0」、C3 で「答えが 0」を扱う。それより前の段階では、問題にも答えの選択肢にも 0 を出さない |
| M9-06 | 引き算で負の数を出さない |
| M9-07 | 分け方は 1と3、2と2、3と1 など、どちらの皿にも1つ以上あれば正解。別の分け方も試すよう促す |
| M9-08 | 数・読み上げ・絵の増減・式が常に一致する（同じ問題データから生成し、テストで確認） |
| M9-09 | 進度は たしざん（A・B）／ひきざん（C）／わける（D）／しきだけ たしざん（E1）／しきだけ ひきざん（E2）で分離 |
| M9-10 | E1 は たしざん が最上段（B3）で「進む」条件を満たした後、E2 は ひきざん が最上段（C3）で満たした後に出す。保護者は早く出すこともできる |
| M9-11 | 速さを評価しない |

## 8. 非機能要件（NF）

| ID | 要件 | 受入条件 |
|---|---|---|
| NF-01 | 技術構成 | TypeScript, React, Vite, 自前の Service Worker による PWA |
| NF-02 | 依存は最小限、版を固定 | package.json は完全一致の版指定、package-lock.json をコミット |
| NF-03 | 型チェック・lint・format | `npm run check` で tsc / ESLint / Prettier |
| NF-04 | 教材データと描画・判定の分離 | 各モードに content（データ）/ logic（純粋関数）/ UI を分ける |
| NF-05 | 判定は純粋関数で単体テスト | Vitest。生成問題は複数seedで検証 |
| NF-06 | 巨大な単一ファイルを避ける | 1ファイル概ね400行以内を目安 |
| NF-07 | 初回表示 | 実機で起動〜ホーム表示 3秒以内を目標（実機で測る） |
| NF-08 | 配布物のサイズ | 音声・フォント込みで 30MB 以下を目標 |
| NF-09 | アクセシビリティ | 主要UIは意味のある HTML 要素（button 等）。色だけで意味を伝えない |
| NF-10 | 検証の区別 | 自動検証済み／手動確認済み／実機未確認を報告で区別 |
| NF-11 | プライバシー | 外部送信なし。ログもすべて端末内 |

## 9. 範囲

### 必須範囲（今回完成させる）
- 全9モード（各モードの全段階）、ホーム、起動画面、完了画面、がんばりノート、保護者画面、複数プロフィール、保存・書き出し・読み込み、オフライン、同梱音声、同梱フォント、Zorin 用の導入スクリプト、テスト。

### 後続の拡張（今回は範囲外）
- 五十音全字の収録（データ構造は対応済み）、濁音・拗音の読み
- おかいもので「注文を覚える」課題、お金
- 6〜10の数、10の合成分解
- 保護者の録音で音声を差し替える機能（今回は台本と素材一覧のみ）
- GitHub Pages 等への公開、自動更新配信
- 多言語
